### Step 1 — Schema migration: `source`, `summary`, `body` (combines nova_new items 1 + 3)

Both items mutate the shard schema. Doing them in one migration pass avoids touching every shard twice.

**Implementation:**
- Add three fields to the shard schema (whichever model — `meta_tags` JSON or `shard_parser.py`'s new format — the prerequisite resolution decided on):
  - `source`: enum `{user_input, external_doc, agent_inference, session_extracted, corroborated_by}`
  - `summary`: ~50-token string, single canonical summary of the shard
  - `body`: full content (the existing conversation/turns payload)
- Backfill all 446 existing shards:
  - `source` defaults to `agent_inference` unless creation context (filename, `meta_tags.origin`, ChatGPT-export marker) gives a stronger signal
  - `summary` generated by Haiku in batch — one call per shard, prompt-cached on a fixed system prompt
- Update every ingestion path to set `source` automatically based on which writer created the shard (`nidhogg_ingest` → `external_doc`, `nova_shard_create` from a tool call → `user_input` or `agent_inference` based on caller, `PostToolUse` hook → `session_extracted`)
- Update retrieval (`ravens.py`, `store.py` keyword search) to weight `agent_inference` lower than externally-sourced shards by a configurable multiplier (env var `NOVA_AGENT_INFERENCE_WEIGHT`, default `0.7`)

**Done when:**
- [ ] All 446 shards have non-null `source`, `summary`, `body`
- [ ] `nova_shard_create`, `nova_shard_update`, `nidhogg_ingest`, `wiki_ingest` all set `source` correctly
- [ ] `ravens.py` applies the inference-weight multiplier in scoring
- [ ] `nova_shard_get_full` MCP tool exists and returns the full body (cold-path fetch)
- [ ] `test_nova.py` smoke test still passes

### Step 2 — Lineage edges (`supersedes`, `corroborated_by`) — was item 7, moved up

Quarantine graduation (step 4) needs these edge types to express *why* a shard graduated or was killed. Build the graph vocabulary before the consumers.

**Implementation:**
- Extend `graph.py` edge types beyond `depends_on`, `influences`, `contradicts`:
  - `supersedes` (with required `reason` field on the edge)
  - `corroborated_by` (no required fields beyond source/target)
- When a new shard contradicts an existing one and wins (higher confidence + corroborating source), automatically write a `supersedes` edge with the explanation
- When a new external source confirms an existing belief, write `corroborated_by`
- **Confidence escalation rule:** confidence may only rise via `corroborated_by` edges, never via repeat retrieval. Enforce in `maintenance.py` and any other writer that mutates confidence upward.

**Done when:**
- [ ] `nova_graph_relate` accepts `supersedes` and `corroborated_by`
- [ ] `nova_graph_query` returns these edge types correctly
- [ ] At least one writer in the codebase emits each new edge type automatically (not just on manual `nova_graph_relate` calls)
- [ ] No code path raises confidence except via `corroborated_by` — grep `maintenance.py`, `store.py`, `ravens.py` to confirm

### Step 3 — Hook recall floor (was item 2, with cluster-aware dedup deferred)

The original item 2 included "cluster-aware deduplication," but clusters are not defined until item 11. Implement the confidence floor now; add cluster-collapse after step 8.

**Implementation:**
- Hook recall config: hard floor at `0.85` confidence, max 3 shards, no top-K floor (return zero results if nothing clears the bar)
- Inject **summary headers only** (~50 tokens — the `summary` field from step 1), never full bodies
- Full body retrievable only via the explicit `nova_shard_get_full` tool added in step 1
- **Defer:** sibling-cluster collapse (revisit after step 8)

**Done when:**
- [ ] A new helper (e.g., `mcp/recall.py:hook_recall(query, top_k=3, min_confidence=0.85)`) exists
- [ ] Returns zero results when nothing clears the floor — verified by a unit test
- [ ] Returns summary headers only, never bodies
- [ ] Has an in-memory LRU cache keyed on `(query_hash, top_k, min_confidence)` with 5-minute TTL

### Step 4 — Quarantine for session-extracted shards (was item 6, moved up before hooks)

If hooks ship before quarantine, `PostToolUse`-extracted shards pollute retrieval on day one. Quarantine must exist before the hook prototype goes live.

**Implementation:**
- Add `quarantine_until` (timestamp, nullable) to shard schema
- Default window: 48 hours. Configurable via `NOVA_QUARANTINE_HOURS` env var.
- Any shard written with `source = session_extracted` gets `quarantine_until = now + window`
- Quarantined shards are retrievable but with a confidence penalty in scoring (multiplier `NOVA_QUARANTINE_PENALTY`, default `0.5`)
- NÓTT pass on `SCHEDULED` trigger:
  - For each shard past `quarantine_until`: graduate (clear the field) if no `contradicts` edge points at it; mark contradicted (`-1` or float equivalent until migration completes) if one does
  - On graduation, write `corroborated_by` edge if any other shard's content matches; otherwise just clear the timestamp

**Done when:**
- [ ] `quarantine_until` field present on shard schema and backfilled to `null` for existing shards
- [ ] All `source = session_extracted` writes set the field
- [ ] Retrieval (`ravens.py`, hook recall) applies the penalty multiplier
- [ ] NÓTT graduation pass runs on schedule and is covered by a smoke test

### Step 5 — Two-hook Claude Code prototype (was item 5)

Now safe to run: schema, lineage edges, recall floor, and quarantine are all in place.

**Implementation:**
- Hook 1 — `UserPromptSubmit`: shells out to `nova-recall --top-k 3 --min-confidence 0.85` and prepends results as system context. Uses the helper from step 3.
- Hook 2 — `PostToolUse` on `Edit`/`Write` only: runs `nova-extract --from-tool-result` to capture decisions as new shards. These shards get `source = session_extracted` and `quarantine_until` automatically (from step 4).
- Tool whitelist for hook firing: `Read`, `Grep`, `Edit`, `Write`. Skip `Bash`, `ls`, `pwd`, etc. Configurable via `NOVA_HOOK_TOOLS` env var.
- Wire hooks via `update-config` skill or document in `CLAUDE.md` how the user enables them in `.claude/settings.json`.
- **Telemetry:** log every injection to `nova_usage.jsonl` with whether the user accepted/rejected the suggestion downstream (best-effort signal — at minimum log the prompt + injected shard IDs).

**Done when:**
- [ ] Both hooks runnable end-to-end on a test session
- [ ] `PostToolUse` writes go through quarantine (verified: `quarantine_until` is set)
- [ ] `nova_usage.jsonl` contains hook-injection entries with shard IDs
- [ ] One-week dogfooding plan documented (run on Forgemaster's own sessions)

### Step 6 — Decay-on-read (was item 8)

**Implementation:**
- Every retrieval logs the shard ID + timestamp to a lightweight access log (could be a new column in `shard_index.json` or a separate `shard_access.jsonl`)
- NÓTT scheduled pass: shards retrieved N times in window M without a new `corroborated_by` edge get a small confidence penalty (configurable: `NOVA_DECAY_ON_READ_THRESHOLD`, `NOVA_DECAY_ON_READ_WINDOW_DAYS`, `NOVA_DECAY_ON_READ_PENALTY`)
- Inverts the natural reinforcement bias

**Done when:**
- [ ] Access log written on every `nova_shard_search`, `nova_shard_interact`, hook recall
- [ ] NÓTT applies the penalty correctly — covered by a unit test

### Step 7 — Outcome-based reinforcement (was item 9)

**Implementation:**
- `forgemaster_runtime.py` already tracks which shards informed each sprint. Surface this as a sprint outcome record.
- After sprint completion, write outcome edges from the sprint shard to contributing shards:
  - Successful sprint → `corroborated_by` edges (which raise confidence per step 2's rule)
  - Failed sprint → flag contributing shards for review; if root-caused to a bad shard, write `contradicts` edge
- Failure root-cause attribution may be manual at first — log enough context that the user can attribute later

**Done when:**
- [ ] Sprint completion writes outcome edges automatically for the success case
- [ ] Failure path documented and at minimum logs "candidates for review"

### Step 8 — State-aware retrieval gating (was item 10)

**Implementation:**
- Add precondition fields to shards: `project_context` (string or list), `validity_window` (start/end timestamps, both nullable), `superseded_by` (shard ID, nullable — populated by `supersedes` edges from step 2)
- Retrieval pipeline: rank by relevance first, then filter by state applicability before injection
- Concrete example: a high-relevance shard about old NOVA architecture is filtered when current project state is "new architecture" (matched against `project_context`)

**Done when:**
- [ ] Shard schema has all three fields, backfilled to null where unknown
- [ ] Retrieval applies the filter — covered by a test where a stale-context shard would have ranked high but is correctly excluded

### Step 9 — Cluster definition via Leiden (was item 11)

**Implementation:**
- NÓTT scheduled pass: run Leiden community detection on the knowledge graph
- Cache cluster membership as a column on each shard (`cluster_id`)
- If/when float confidence migrates to discrete `{-1, 0, 1}`: enforce simplex sum=1 invariant per cluster via SQL trigger (only relevant post-`shard_parser.py` migration — coordinate with that effort)
- Recompute clusters when graph topology changes meaningfully — NÓTT decides the threshold (start with: recompute when >5% of edges added/removed since last run)

**Done when:**
- [ ] `cluster_id` populated on every shard
- [ ] NÓTT recompute trigger working
- [ ] **Then go back to step 3** and add sibling-cluster collapse to hook recall: if multiple top hits share a `cluster_id`, return the highest-confidence one + a pointer to siblings

### Step 10 — Adversarial NÓTT pass (was item 12)

**Implementation:**
- Weekly cycle: take top N highest-confidence shards
- Run them through a non-Claude model (Gemini or local Nemotron) for contradiction hunting
- Findings become `contradicts` edges with provenance back to the adversarial pass (new `source` value or distinct `meta_tags.origin` so adversarial findings are traceable)
- Different training distribution = independent error pattern. The point is heterogeneity, not capability — even a weaker model is useful here.

**Done when:**
- [ ] Adversarial pass runs on schedule
- [ ] Findings traceable to the pass via provenance
- [ ] At least one end-to-end run completed and reviewed
