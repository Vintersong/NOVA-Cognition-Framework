## What Was Built

### Bug fixes
- Fixed 3 broken quarantine tests + 1 dummy test (`mcp/test_quarantine.py`)
- Fixed production UTC bug: `nova_hook_extract.py` and `nova_server.py` were writing `quarantine_until` with naive `datetime.now()` — switched to `now_utc()` from `timeutils.py`. On non-UTC machines this was silently extending every quarantine window by the local TZ offset.
- Fixed ravens.py timeout race: `asyncio.wait_for` and `httpx.Timeout` were the same value (`_RAVEN_API_TIMEOUT = 10s`), causing asyncio to cancel the task wrapper while the thread stayed alive. Fixed by setting asyncio timeout to `_RAVEN_API_TIMEOUT + 3.0` so httpx always fires first and exits the thread cleanly.

### SQLite secondary index (`mcp/nova_shard_db.py`)
- Structured integer encoding from the Balatro design doc: `state = CCCC_V_A_E` (confidence × valence × arousal × epistemic)
- `NovaShardDB` class with schema, upsert, rebuild, range query, keyword search, stats
- Hooked into `store.save_shard` — every write syncs to SQLite automatically
- `utilities/build_nova_shard_db.py` — CLI rebuild (561 shards indexed on first run)
- New MCP tool: `nova_shard_query_state` — single-predicate range queries over the state vector

### NÓTT valence/arousal pass
- Runs on SCHEDULED trigger alongside adversarial/cluster/decay-on-read
- Batches 15 unscored shards per Haiku call, parses `<va id v a>` XML response
- Writes `valence` + `arousal` back to shard JSON and SQLite in one pass
- Default: valence=5, arousal=5 (neutral) until NÓTT scores them
- Epistemic derived from confidence: ≥0.85 → confirmed, <0.40 → contradicted, else neutral
