# store.py

**One-line purpose:** All filesystem I/O for shards and their indexes — load, save, index rebuild, skeleton reads, summary index management, and the legacy keyword-search fallback.

## Why it exists

Centralises shard I/O so no other module opens shard files directly, and provides path traversal protection (`load_shard` validates that the resolved path stays inside `SHARD_DIR`). File locking (`filelock`) prevents concurrent write corruption.

## Key concepts

- **shard skeleton** — lightweight dict extracted from a shard file without loading the full conversation history. Used by `nova_shard_index` to build the browse view efficiently. Uses `ijson` for streaming parse when available.
- **summary index** (`summary_index.json`) — secondary index keyed by `shard_id`; stores a one-line summary sentence (`d`) and a longer synopsis (`s`) for each shard. Generated by Haiku or derived heuristically from `guiding_question`.
- **browse row** — compact dict `{id, d, t, c, created, n}` used for the index/list tool responses.
- **`guess_relevant_shards`** — legacy token-overlap fallback; called when HUGINN is unavailable.

## Public surface

- `load_shard(shard_id) → (dict, str)` — load shard JSON; raises `ValueError` on path traversal, `FileNotFoundError` if absent.
- `save_shard(filepath, data)` — file-locked JSON write.
- `update_shard_usage(data)` — increments `meta_tags.usage_count` and sets `meta_tags.last_used`.
- `extract_fragments(shard_data, shard_id) → list[str]` — returns formatted context fragments from `conversation_history`.
- `load_index() / save_index(index)` — load/save `shard_index.json`.
- `update_index() → dict` — full rescan of `SHARD_DIR`; writes and returns the new index.
- `patch_index_entry(shard_id, shard_data) → dict` — update one entry without full rescan.
- `classify_tags(shard) → list[str]` — derive status tags: `recent`, `stale`, `frequently_used`, `archived`, `forgotten`, `enriched`, `low_confidence`, `compacted`.
- `iter_shard_skeletons() / read_shard_skeleton(path)` — stream lightweight metadata.
- `collect_browse_rows() / filter_sort_paginate_rows() / group_rows_by_theme()` — build and filter browse index.
- `load_summary_index() / save_summary_index() / rebuild_summary_indexes()` — summary index management.
- `generate_haiku_summary_batch(shards, batch_size)` — call Haiku to generate summary sentences.
- `guess_relevant_shards(message, index, top_n)` — legacy keyword fallback.

## Inputs and outputs

- **Reads:** `SHARD_DIR/*.json`, `INDEX_FILE`, `SUMMARY_INDEX_FILE`.
- **Writes:** same files (file-locked via `filelock`). Also writes `SUMMARY_MARKDOWN_FILE`.
- **Env:** `NOVA_SHARD_DIR`, `NOVA_INDEX_FILE`, `NOVA_SUMMARY_INDEX_FILE`, `NOVA_SUMMARY_MARKDOWN_FILE`, `CLAUDE_API_KEY`, `HUGINN_MODEL`.
- **Optional dep:** `ijson` for streaming JSON parse — falls back to `json.load` if absent.

## Invariants and assumptions

- All shard files are flat `*.json` in `SHARD_DIR` — no subdirectory recursion.
- Float confidence is read from `meta_tags.confidence` (default 1.0). The `low_confidence` tag is assigned when this float falls below `CONFIDENCE_LOW_THRESHOLD`.
- `classify_tags` checks `shard.get("context", {}).get("embedding")` for `enriched` — most shards lack this.
- `extract_fragments` reads `conversation_history` with `{user, ai}` turn format; `autoresearch.py` shards use `turns` with `{role, content}` — those shards produce no fragments.

## Callers and integration

Imported by `nova_server.py`, `maintenance.py`, `nidhogg.py`, `evolve.py`, and `utilities/shard_index.py`. The most widely used module in `mcp/`.

## Known gaps / open questions

- Float confidence is read and stored throughout — `update_index`, `patch_index_entry`, `_build_skeleton_from_full_data`, `build_browse_row` all handle confidence as float. All must be updated when migration to discrete `{-1, 0, 1}` completes.
- `generate_haiku_summary_batch` parses the Haiku response as raw JSON (`json.loads(raw)`) with no fallback if the model returns anything other than a JSON array. Fragile.
- `extract_fragments` does not handle the `turns` format used by autoresearch shards — those will always show as empty in context.
- `cosine_similarity` is also implemented in `maintenance.py` and `wiki_tools.py` — three copies of the same function exist.
