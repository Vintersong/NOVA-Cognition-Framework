# evolve.py

**One-line purpose:** NOVA's self-evolution loop — analyze shard health, run tests, auto-commit passing changes, rotate focus areas, and return a PRODUCT DIRECTOR prompt for the next sprint.

## Why it exists

Inspired by Bernstein's `evolve_mode.py`. The goal is to keep NOVA improving itself between manual sessions: surface what needs attention, verify the codebase is healthy, commit clean changes automatically, and guide the next Forgemaster sprint toward high-impact work. Key difference from Bernstein: improvement tasks become NOVA shards (not HTTP task server tickets), and the current Claude session acts on the report.

## Key concepts

- **Pipeline** — 6 steps per cycle: ANALYZE → VERIFY → COMMIT → GOVERN → PLAN → LOG.
- **`AdaptiveGovernor`** (`_adjust_weights` + `_pick_focus`) — adjusts focus area weights based on health signals (low confidence, test failures, nidhogg backlog). Uses weighted deterministic rotation via `cycle_count % len(top2)` to ensure all areas get attention over time.
- **6 focus areas** — `shard_health`, `nidhogg_pipeline`, `forgemaster_skills`, `nova_server`, `test_coverage`, `documentation`. Each has a specific instruction prompt injected into the PRODUCT DIRECTOR output.
- **`_auto_commit`** — stages non-runtime files, runs pytest, commits on pass, rolls back changed files on failure. Writes `.sdd/runtime/restart_requested` if `mcp/` source files changed.
- **`evolve.json`** — persists cycle state: `_cycle_count`, `_last_cycle_ts`, `_consecutive_empty`, `_focus_weights`. Governor reads/writes this file on every cycle.
- **Rate limiting** — minimum `interval_s` (default 300s) between cycles; `max_cycles` and `budget_usd` caps (0 = unlimited).

## Public surface

- `run_evolve_cycle(dry_run, force) → dict` — main entry point. Returns full cycle result including `director_prompt`.
- `register_evolve_tools(mcp)` — registers `nova_evolve` tool onto a FastMCP instance.

## Inputs and outputs

- **Reads:** `shard_index.json`, shard JSON files, `evolve.json`, `tests/`.
- **Writes:** `evolve.json` (cycle state), `evolve_cycles.jsonl` (cycle log), `.sdd/runtime/restart_requested` (if `mcp/` changed), any files committed by `_auto_commit`.
- **Env:** inherits all config from `config.py`; reads git and pytest from PATH.

## Invariants and assumptions

- `_shard_health` reads float confidence from the index — incompatible with discrete confidence model. `avg_confidence < 0.7` threshold for weight boosting is meaningless if confidence values are `{-1, 0, 1}`.
- `_auto_commit` excludes runtime files from staging (`.sdd/`, `evolve_cycles.jsonl`, `nova_usage.jsonl`, `shard_index.json`, `shard_graph.json`, `nidhogg_manifest.json`, `shards/`). All other tracked files are staged.
- Rollback on test failure uses `git checkout -- <changed_files>` (targeted, not `git checkout -- .`) — only the files the cycle touched are rolled back, not the entire working tree.
- `merge_candidates` in `ShardHealthReport` is `max(0, enriched // 5)` — a rough heuristic proxy, not a real embedding comparison.

## Callers and integration

- `nova_server.py` — calls `register_evolve_tools(mcp)` at startup.
- No other callers.

## Known gaps / open questions

- `_shard_health` uses float confidence — blocked by the discrete confidence migration.
- `_build_director_prompt` instructs Claude to create `nova_shard` entries but does not call any tools itself — the entire PLAN step is a prompt template returned as text. The calling Claude session must act on it manually.
- `budget_usd` tracking is never incremented in the current code — the field exists in `evolve.json` but `_spent_usd` is never updated after API calls.
- No mechanism to prevent `_auto_commit` from committing documentation files generated by this very archaeology pass.
