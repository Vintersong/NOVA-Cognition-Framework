# NOVA Repository Audit — 2026-05-12

## Executive Summary

Independent audit of `D:\NOVA-Whitepaper`, comparing on-disk reality against the documented inventory in `CLAUDE.md`, `mcp/SKILL.md`, `forgemaster/SKILL_LIBRARY.md`, `forgemaster/AGENTS.md`, and `forgemaster/STANDARDS.md`. Findings produced by three Claude Code Explore passes and verified by an independent Codex pass.

**Top 5 issues, ranked by severity:**

1. **🛑 Security gap — permission bypass.** `nova_facts_search` and `nova_facts_rebuild` (in `mcp/facts.py`) are fully registered MCP tools but are **absent** from the `_ALL_TOOL_NAMES` whitelist tuple in `mcp/nova_server.py` (lines 268–307). They bypass the project's permission gate. **Held for a focused PR, not patched in this pass.**
2. **Tool inventory drift.** `CLAUDE.md` claimed 31 MCP tools; the code registers 35 across `mcp/`. Two registered tools (`nova_shard_query_state`, `nova_obsidian_export`) and a whole module (`facts.py`, 2 tools) were undocumented. `mcp/SKILL.md` was also stale (30, missing `nova_shard_get_full`). **Fixed in this pass.**
3. **Forgemaster library catastrophically under-indexed.** `CLAUDE.md` claimed 208 files / 15 categories; on disk: **324 files / 25 categories**. 12 whole categories had no index entry in `SKILL_LIBRARY.md` (the largest, `mlops/`, alone holds 18 skills). **Fixed in this pass.**
4. **Agents directory mixes personas with reference material.** `CLAUDE.md` claimed "326 agent persona definitions"; on disk: 320 `.md` files, of which only **221 are true personas** (have a `name:` frontmatter field). The remaining ~99 are runbooks, examples, engine docs, and strategy material. Naming convention has 24 outliers (`spatial-computing/` 6/6, `specialized/` 18/27). Three different frontmatter schemas in active use. **Doc fix applied; structural cleanup deferred.**
5. **Empty placeholder category.** `forgemaster/library/optional-skills/` exists but contains no skills. Flagged for cleanup.

### Security gap detail

`mcp/nova_server.py` lines 270–306 define `_ALL_TOOL_NAMES` (tuple used by `permissions.py` to gate which tools the server exposes). Codex confirmed the tuple lists 33 names; **`nova_facts_search` and `nova_facts_rebuild` are not present**. `facts.py` itself contains no permission-gate references. The tools are still imported and registered via `nova_server.py:132` and `nova_server.py:262`.

This means the facts tools execute regardless of which permission profile is loaded — they bypass the gate entirely. Severity: **high** for any deployment that relies on `_ALL_TOOL_NAMES` to scope tool access.

**Fix held for a separate PR** so it can be reviewed as a security change rather than mixed in with cosmetic doc edits. Exact 2-line patch is drafted in `AUDIT-2026-05-12-followup.md`.

## C. Forgemaster Agents (`forgemaster/agents/`)

### Inventory

- Claimed: **326** persona definitions across 18 divisions.
- Actual: **320** total `.md` files across 18 divisions. Of those, **221** have a `name:` frontmatter field within their first 10 lines (Codex's precise count) — these are the true dispatchable personas. The remaining ~99 are reference material:
  - `examples/` — workflow examples (no `name:`)
  - `research/program.md` — research program doc
  - `strategy/` — 16 runbook/playbook files (no `name:`)
  - `game-development/engine-reference/`, `blender/`, `godot/`, `unity/`, `unreal-engine/`, `roblox-studio/`, `studio-docs/` — engine reference and team-process docs

`AGENTS.md` itself never enumerated 326 agents; CLAUDE.md's directory line was the only place that count appeared.

### Naming outliers

| Division | Convention | Outliers |
|---|---|---|
| Most (14 divisions) | `{division}-{persona}.md` | 0 |
| `game-development/` | `game-development-{persona}.md` | minor — double "game" prefix is intentional |
| `spatial-computing/` | (none) | **6 / 6** files lack `spatial-computing-` prefix (`xr-interface-architect.md`, `macos-spatial-metal-engineer.md`, etc.) |
| `specialized/` | `specialized-{persona}.md` | **18 / 27** files lack the prefix |
| `openFang/` | mixed | non-kebab and TOML alternate formats (`openfang-agents/*.toml`, 30 files) |

### Frontmatter schema drift

Three schemas in active use across persona files:

- **Base** — `name`, `description` only (e.g. `academic/`).
- **Metadata-extended** — adds `color`, `emoji`, `vibe` (~80 files, mostly `marketing/`, `specialized/`, `product/`).
- **Technical-extended** — adds `tools`, `model`, `maxTurns`, `disallowedTools` (~30 files, mostly `game-development/studio-agents/`).

No agent is missing the base pair. No persona-name collisions detected across divisions (all 221 unique).

### What was changed in this pass

- `AGENTS.md` now contains a "Repository Layout — Personas vs. Reference Material" note distinguishing the 221 personas from the ~99 reference files and flagging the planned move into `forgemaster/resources/`.
- `CLAUDE.md` directory line updated from "326 files, 18 divisions" to "221 personas + 99 reference files, 18 divisions".

Renames, frontmatter unification, and the `agents/ → resources/` migration are **deferred** to the follow-up PR — see `AUDIT-2026-05-12-followup.md`.
